# Contributing

Thanks for helping. A few rules keep review manageable for a small team.

## Before you open a pull request

- Open or comment on an issue first for anything bigger than a typo, so we agree on the change before you build it.
- One change per pull request.
- Say what you checked: the commands you ran, the logs you tested against, what you saw.

## Using AI tools

You're welcome to use coding agents. We do too. You are still the author:

- Read and understand every line you submit, and be ready to answer questions about it.
- Run it yourself before opening the pull request.
- Don't open pull requests from agents running unattended.

Maintainers may close pull requests that look unreviewed, or that don't follow these rules, without a detailed review.

## Privacy

Never commit real usage logs, even your own. Use the sample-data generator or the redacted fixtures in the test folder.
